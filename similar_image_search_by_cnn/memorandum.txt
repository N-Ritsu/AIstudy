・開発目的
事前学習済みのCNNモデルを応用したシステム開発の経験を積むため。

・技術選定理由
- 事前学習済みVGG16（特徴抽出）：ImageNetで学習済みの表現を流用し、ゼロからの学習コストを避けつつ意味的な特徴を得る。
- コサイン類似度：ベクトルの向きの近さで比較し、明るさなどのスケール差に比較的頑健。
- 特徴量の事前計算＋pickle保存：検索時の再抽出を避け、応答を高速化。
- CIFAR-10の特定クラス（猫）を検索対象に用意。
- torch / torchvision / scikit-learn：モデル・前処理・類似度計算の標準構成。

・主な設定値
- 特徴抽出：VGG16の features（畳み込み・プーリング部）＋ avgpool の出力を flatten し、512×7×7 = 25088次元のベクトルとして扱う（分類層は使わない）。
- 検索対象：猫画像500枚。クエリ画像と同じ画像自身は結果から除外し、類似度上位5件を表示。

・苦戦した点
- 毎回全画像から特徴を取り直すと遅く、使い物にならない点。
- 分類モデルを検索用の特徴抽出器としてどう使うかの設計。
- データ準備・特徴抽出・検索を一つのスクリプトにすると保守しにくい点。
- 検索実行時に ValueError: Expected 2D array, got 1D array instead が発生した。

・苦戦点の解決法、工夫点
- オフライン／オンラインを分離：download_data → extract_features（全画像の特徴を.pkl化）→ 検索本体、の3段階に分割。
- 検索時は保存済み特徴を読み込み、クエリ画像だけ特徴抽出してコサイン類似度で上位を取得。
- クエリと類似画像を並べて可視化し、結果を直感的に確認できるようにした。
- ValueErrorは、cosine_similarityは「サンプル数×特徴数」の2次元配列を要求するが、特徴抽出メソッドの末尾で余分に .flatten() していたため、クエリの特徴量が (25088,) の1次元になっていたのが原因だと分かった。
- ValueErrorは、余分な .flatten() を削除し、クエリの特徴量を (1, 25088) の2次元形状のまま渡すことで解消した。各段階でテンソル・配列の形状を確認する習慣がついた。

・得られた学び
- 事前学習モデルは分類だけでなく、特徴抽出器として応用できること。
- 重い処理を事前計算し永続化すると、検索システムの実用性が大きく上がること。
- 目的ごとにスクリプトを分けると、再利用とデバッグがしやすいこと。

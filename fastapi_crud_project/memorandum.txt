・開発目的
モデルを載せるだけでなく、品質を自動で担保し、デプロイ可能な成果物を継続的に作るMLOps/DevOpsの基本を実践するため。

・技術選定理由
- FastAPI + Pydantic：型ヒントとスキーマ検証で堅牢なAPIを素早く構築。Swagger UIも自動生成。
- pytest + TestClient：サーバーを実際に起動せずに正常系・異常系を自動テスト。
- Docker：依存関係込みでポータブルな実行環境を定義。
- GitHub Actions：push/PRをトリガーにテストし、イメージビルド＆Docker Hubプッシュを自動化。
- データは学習用にインメモリ辞書。lifespanで起動時に初期化。

・苦戦した点
- 初めての本格的なCI/CDで、テスト・コンテナ・レジストリ連携を一つのワークフローにまとめる設計が難しかった。
- ローカルでは動くが、Actions上の環境差分で落ちないようにするrequirements.txtやDockerfile等の調整。

・苦戦点の解決法、工夫点
- 入力用UserInと出力用UserOutを分け、クライアントがIDを不正指定できないようにした。
- lifespanでサーバー起動時にサンプルユーザーデータを投入し、デモしやすい状態にした。
- TestClientで、外部への通信を行わずとも、エンドポイントの正常系・異常系テストをカバー。
- CIでpytestを必須にし、成功時のみDockerイメージをビルドしてDocker HubへpushするCDを組んだ。
- イメージはdocker pull→docker runするだけでSwagger UIから試せるようにした。

・得られた学び
- テスト・コンテナ・CI/CDを個別に知るだけでなく、つなげて自動化すると効率と信頼性が大きく上がること。
- "ただ動くコード"ではなく"いつでもデプロイできる"物として作る意識が重要であること。
- スキーマ駆動と自動ドキュメントがあると、APIの利用・検証が格段に楽になること。
